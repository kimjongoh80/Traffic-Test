Traffic-Test 사용설명서

네트워크 장비 양 끝단에 PC를 연결해 TCP/UDP 대역폭, 지연시간, 지터, 패킷 손실을 측정하는 트래픽 스트레스 테스트 도구

1. 준비물과 구성

  • PC 2대 (Windows 10/11 또는 macOS 11 이상, 섞어서 써도 됩니다)
  • 시험할 네트워크 장비 (스위치, 라우터, 방화벽, 회선 등)
  • 두 PC에 Traffic-Test
[ Server PC : 트래픽 송신 ] ── 시험 대상 장비 ── [ Client PC : 트래픽 수신 ] 192.168.1.10 192.168.1.20

두 PC 모두 같은 프로그램을 실행합니다. 한 대는 Server(트래픽을 보내는 쪽), 다른 한 대는 Client(트래픽을 받는 쪽)로 씁니다. 테스트는 Client PC에서 시작합니다.

2. 설치

Windows

  1. TrafficTest-버전-windows-x64.zip 압축을 원하는 폴더에 풉니다. (ARM 노트북은 windows-arm64)
  2. TrafficTest.exe를 더블클릭합니다.
  3. "Windows의 PC 보호" 창이 나오면 추가 정보 → 실행을 누릅니다.
  4. Traffic-Test 앱 창이 열립니다. 창을 닫으면 프로그램이 끝납니다.

macOS

  1. Apple Silicon(M1 이상) Mac은 macos-apple-silicon.zip, Intel Mac은 macos-intel.zip을 받아 압축을 풉니다.
  2. TrafficTest.app을 응용 프로그램 폴더로 옮깁니다(선택).
  3. 처음 한 번은 앱을 Control 키를 누른 채 클릭 → 열기로 실행합니다. 서명되지 않은 앱이라 그냥 더블클릭하면 막힐 수 있습니다.
    그래도 막히면 시스템 설정 → 개인정보 보호 및 보안 아래쪽의 그래도 열기를 누릅니다.
  4. "들어오는 네트워크 연결을 허용하겠습니까?"가 나오면 허용을 누릅니다.
  5. Traffic-Test 앱 창이 열립니다. 창을 닫거나 ⌘Q를 누르면 프로그램이 끝납니다.
앱 창은 Windows에 기본으로 들어 있는 Microsoft Edge WebView2를 사용합니다. 오래된 Windows에서 WebView2가 없으면 기본 브라우저로 화면이 열립니다. 이때는 화면 오른쪽 위 종료 버튼으로 끝냅니다.

3. 방화벽 설정

상대 PC가 보내는 테스트 트래픽이 들어올 수 있게 두 PC 모두 방화벽을 열어야 합니다.

프로토콜포트용도
TCP5210제어 연결, TCP 테스트 데이터
UDP5210지연시간(RTT) 측정
UDP5211 ~ 5210+스트림 수UDP 테스트 데이터 (최대 5338)
  • Windows: 함께 들어 있는 Allow-Firewall.bat을 더블클릭하고 관리자 권한을 허용합니다. 한 번만 하면 됩니다. 되돌릴 때는 Remove-Firewall.bat.
  • macOS: 처음 실행할 때 나오는 연결 허용 창에서 허용을 누르면 됩니다.
  • 시험 대상이 방화벽 장비라면 장비 정책에도 위 포트를 열어 주세요.

4. 테스트하기

Server PC (트래픽을 보내는 쪽)

  1. Traffic-Test를 실행하고 Mode에서 Server를 고릅니다.
  2. 화면에 표시된 Client PC에 입력할 이 PC의 주소를 확인합니다.
  3. 서버 시작을 누릅니다. "Client 연결 대기 중"이 표시되고, 이 상태에서는 트래픽을 보내지 않습니다.
  4. Client PC가 테스트를 시작하면 그때 트래픽을 보내며, Server 화면에서도 그래프와 결과를 실시간으로 볼 수 있습니다. 테스트가 끝나면 다시 대기 상태로 돌아갑니다.

Server는 모든 네트워크 주소에서 연결을 받으므로 Client의 IP를 따로 입력할 필요가 없습니다.

Client PC (트래픽을 받는 쪽)

  1. Traffic-Test를 실행하고 Mode에서 Client를 고릅니다.
  2. Server PC 주소에 Server 화면에 표시된 IP를 입력합니다.
  3. 프리셋을 고르거나 프로토콜, 시간, 스트림, 목표 대역폭, 합격 기준을 설정합니다.
  4. 테스트 시작을 누르면 Server가 이 PC로 트래픽을 보냅니다. 중간에 멈추려면 테스트 중지를 누릅니다(그때까지의 결과는 저장됩니다).
반대 방향 성능을 보려면 두 PC의 Mode를 서로 바꿔 한 번 더 테스트하세요. 장비가 한쪽 방향에서만 느린 경우를 찾을 수 있습니다.

7. 결과 보기와 판정

지표의미
대역폭받는 쪽에서 1초마다 측정한 실제 처리량. 평균·최소·최대 표시
지연시간 (RTT)테스트 트래픽이 흐르는 동안 측정한 왕복 시간. 장비가 부하를 받을 때 지연이 얼마나 늘어나는지 보여 줍니다(평균, p95, 최대)
지터UDP: 패킷 도착 간격의 흔들림(RFC 3550). TCP: RTT 변동
패킷 손실UDP: 보낸 패킷 중 도착하지 않은 비율, 순서 뒤바뀜 포함. TCP는 재전송으로 손실이 보정되므로 RTT 측정 패킷의 손실률을 표시

합격 기준을 열고 최소 대역폭, 최대 손실, 최대 RTT, 최대 지터를 입력하면 그래프에 빨간 점선이 그려지고, 테스트가 끝나면 PASS / FAIL과 항목별 결과가 표시됩니다. 비워 둔 항목은 판정하지 않습니다.

모든 결과는 Server와 Client 양쪽에 자동 저장되고 테스트 이력에서 다시 열 수 있습니다.

  • Windows: 프로그램 폴더 안 results 폴더 (쓰기 권한이 없으면 사용자 폴더\TrafficTest\results)
  • macOS: 문서/TrafficTest/results

저장 위치를 바꾸려면 테스트 이력의 찾아보기…로 폴더를 고르거나, 경로를 입력하고 적용을 누릅니다. 칸을 비우고 적용하면 기본 폴더로 돌아갑니다. 이미 저장된 결과는 원래 폴더에 남아 있고, 이력 목록에는 새 폴더의 결과가 보입니다. 폴더 열기는 탐색기(Finder)에서 저장 폴더를 엽니다.

화면 오른쪽 위에서 테마(시스템 설정 / 라이트 / 다크), 글자 크기, 화면 배율을 고를 수 있습니다. 글자는 A− / A+로 10%씩 70~200% 사이에서 조절하고, 가운데 %를 누르면 100%로 돌아갑니다. 화면은 창 크기에 맞춰 자동으로 줄어들고, 화면 메뉴는 전체 배율을 조절합니다. 이 설정과 저장 위치는 다음 실행 때도 유지됩니다.

9. 10G / 25G 테스트

  • TCP는 병렬 스트림을 4~8로 늘리세요. 스트림 1개로는 PC 성능 때문에 회선 속도를 다 못 쓸 수 있습니다.
  • UDP 고속 테스트는 초당 패킷 수가 한계가 됩니다. 장비와 양쪽 NIC에서 점보 프레임(MTU 9000)을 켜고 패킷 크기를 8972로 설정하세요(25G UDP 점보 프리셋).
  • 양쪽 PC의 NIC, PCIe 슬롯, CPU가 결과에 영향을 줍니다. 장비 없이 두 PC를 직접 연결해 기준 성능을 먼저 재 두면 장비 성능을 판단하기 쉽습니다.
  • 노트북은 전원 연결, 고성능 모드에서 테스트하세요.

10. 문제 해결

증상확인할 것
"cannot connect to server"Server PC에서 서버 시작을 눌러 "Client 연결 대기 중"인지, IP가 맞는지, Server PC 방화벽(TCP 5210)이 열렸는지 확인하세요. ping이 되는지도 확인하세요.
"no UDP packets reached the server"UDP 5211 이상 포트가 방화벽이나 시험 장비에서 막혀 있습니다.
RTT가 "-"로 나옴UDP 5210이 막혀 있습니다. 대역폭 측정에는 영향이 없습니다.
"server is busy"상대 PC가 이미 다른 테스트를 하고 있습니다. 끝난 뒤 다시 시도하세요.
UDP 손실이 높음목표 대역폭이 회선 속도보다 높지 않은지 확인하세요. 1G 회선이면 950 Mbps 이하가 적당합니다. 받는 PC의 CPU 사용률도 확인하세요.
속도가 기대보다 낮음병렬 스트림을 늘리고, 링크 속도(1G/10G 협상), 케이블, 이중(Duplex) 설정을 확인하세요.
"포트 5210 사용 중" 오류Traffic-Test가 이미 실행 중이거나 다른 프로그램이 포트를 쓰고 있습니다. 실행 중인 Traffic-Test를 종료하세요.

11. 명령줄 사용

스크립트나 원격 접속 환경에서는 명령줄로도 쓸 수 있습니다. Windows는 zip 안의 ttest.exe, macOS는 ttest를 사용하세요.

# Server PC: 대기
ttest server

# Client PC: Server가 보내고 이 PC가 받기(-R), TCP 30초, 스트림 4, 보고서와 CSV 저장
ttest client -c 192.168.1.10 -R -t 30 -P 4 --report report.html --csv result.csv

# UDP 1 Gbps 수신
ttest client -c 192.168.1.10 -R -u -b 1G

-R을 빼면 반대로 Client가 보내고 Server가 받습니다. 전체 옵션은 ttest client -h로 볼 수 있습니다.
